# Increment 2 — Core Playback and Background Media Service

## Objective

Turn the local library into a correct background-capable music player without introducing Telegram, downloads, or adaptive playback.

## Implementation checklist

### A. Playback engine and Android service

- [x] Use Media3 ExoPlayer as the playback engine
- [x] Host ExoPlayer and MediaSession in a `MediaSessionService`
- [x] Declare media-playback foreground-service and wake-lock permissions
- [x] Publish Media3 notification, lock-screen, Bluetooth, and system controls
- [x] Keep playback alive when the activity leaves the foreground
- [x] Hold a playback wake lock while audio is active with the screen off

### B. Audio behavior and recovery

- [x] Delegate audio-focus handling to ExoPlayer
- [x] Pause automatically when a headset route becomes noisy/disconnects
- [x] Handle seek, previous, next, play, and pause commands
- [x] Advance to the next item after a track error
- [x] Stop recoverably when the final item fails
- [x] Keep Media3 and service types behind the domain `PlaybackController`

### C. Queue construction and state persistence

- [x] Resolve playable local URIs through a domain-facing playback catalog
- [x] Build an ordered queue from available local tracks
- [x] Persist queue items, current index, position, playback mode, and repeat state
- [x] Restore the previous session after normal process recreation
- [x] Restore paused rather than starting audible playback automatically
- [x] Safely discard corrupt persisted state

### D. Now Playing UI

- [x] Open Now Playing by selecting a library track
- [x] Display artwork, title, artist, elapsed time, and remaining time
- [x] Provide a seek slider
- [x] Provide previous, play/pause, and next controls
- [x] Display preparing, buffering, paused, playing, and error states
- [x] Preserve the UI-to-domain boundary; Compose does not access ExoPlayer directly

### E. Verification

- [x] Playback service play/pause/seek/next device test
- [x] Media notification device test
- [x] Broken-item queue recovery device test
- [x] Session codec round-trip and corruption unit tests
- [x] Real MP3, M4A, FLAC, OGG, Opus, and WAV playback smoke test
- [x] Background and screen-off playback smoke test
- [x] System pause/play/next command smoke test
- [x] Process-stop and paused-session restoration smoke test
- [x] Assemble, lint, unit-test, and connected-device gates

## Acceptance verification — 2026-09-17

- 13 JVM tests passed.
- 6 Android emulator tests passed.
- Playback remained active with the activity backgrounded and the screen off.
- The Media3 foreground notification exposed previous, pause/play, and next actions with current metadata.
- System media-session pause, play, and next commands controlled the active queue.
- A forced process stop restored the six-item queue, active item, and saved position without automatically resuming audio.
- The unavailable-item device test advanced to the next playable item without crashing.
- Physical headset removal cannot be generated by an unprivileged headless emulator. The production player uses Media3's `setHandleAudioBecomingNoisy(true)` route-disconnect behavior.
- Android lint completed with zero errors.

## Non-goals

- Telegram
- downloads
- adaptive playback
- Increment 3 queue editing and shuffle modes
