# Telegram connection recovery and proxies

- Telegram transport runs through the existing TDLib client. Network loss is reported from `UpdateConnectionState`; TDLib owns reconnection. UI shows waiting/connecting/proxy/updating/ready rather than falsely claiming connectivity from authorization alone.
- **Reset connection** requests an orderly native `Close`, keeps collectors attached until closure, then recreates the client from the existing `noBackupFilesDir/tdlib` database. It does not log out, call `Destroy`, wipe credentials, remove imported tracks, or touch pinned offline files. A slow close keeps listening for a late `AuthorizationStateClosed`. Repeated unexpected closures have bounded retries; the user can reset after these are exhausted. A missing API ID/hash is a build-time configuration error, not a network failure.
- Proxy records and credentials are managed by TDLib's local session store, not copied into DataStore, app logs, or backups. The management screen is available before authorization and on a failed connection. The supported types are MTProto, SOCKS5 and HTTP. Only one proxy can be active; Direct disables the active proxy.
- Supported share links: `tg://proxy`, `tg://socks`, `https://t.me/proxy`, `https://t.me/socks`, the corresponding `telegram.me` aliases, and bare `t.me/...`. A foreground clipboard check when the Telegram screen resumes proposes importing a valid copied link. No background clipboard monitoring, silent imports, auto-enable, or unprompted proxy changes.
- A Ping action invokes TDLib `PingProxy(proxyId)` (or `0` for direct) to measure a Telegram server response through that path. The displayed value is measured latency, not an ICMP echo to the proxy and not a guarantee of future availability. Timeouts/errors are recoverable; secret-bearing raw TDLib exceptions are not displayed.
- The native Android media/notification service remains independent of Telegram availability; local/offline playback keeps working through network outages.
- Tests: the proxy link parser covers formats, encoding, invalid input, and clipboard extraction. Android CI runs the normal unit/instrumentation suites. A network/proxy outage or ISP filtering cannot be simulated deterministically by local unit tests; validate a real device against both a working and an unreachable proxy before release.

Reference: https://core.telegram.org/tdlib/docs/ (GetProxies / AddProxy / EnableProxy / DisableProxy / RemoveProxy / PingProxy); https://core.telegram.org/api/links (proxy links).
